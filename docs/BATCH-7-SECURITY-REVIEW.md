# Batch 7 security review

Code review and local security checks completed. Backend regression and expanded sync/adversarial tests passed. No unresolved server authorization or RLS blocker was identified by these checks; this is not an independent penetration assessment. Final gate results are recorded in BATCH-7-REPORT.md.

Retained server authorization, forced domain RLS, opaque HttpOnly sessions, exact-origin CSRF, private evidence retrieval, bounded image normalization, immutable audit/milestones and trip-version checks. The new sync command surface delegates to existing command implementations. It accepts no client-supplied organization/driver/actor authority. Receipt lookups happen after current assignment/permission authorization, preventing known-key replay from revealing another driver's result. Persistent receipts force actor+tenant RLS and commit atomically with the authoritative command.

The local threat model explicitly includes edited IndexedDB and device clock. Those values never bypass server validation. Browser data is NOT encrypted at rest. Same-origin XSS/device access can expose pending photos/signatures; existing nonce CSP and React text escaping are retained. No unsafe HTML, token persistence, signed URLs, public evidence mounts, third-party scripts or raw binary logging were introduced. Static service-worker caches contain only public resources and a non-personalized boot document.

Local access expires after 12 hours; known expired/rejected sessions lock access until same-account reauthentication. Logout/account switching warns before discarding pending data and clears all stores. Server assignment/session revocation cannot be discovered offline; it is checked at reconnect and replay. Conflicts block later commands; no automatic status rollback/rebase or historical rewrite occurs. Storage failure must be visible before a local-save claim. Background/foreground workers share a browser lock, while server serialization/version checks protect separate devices.

Residual risks: device loss/eviction before sync, device administrators/XSS, delayed detection of revocation while offline, browser-dependent background scheduling, accumulating public old-build cache entries, local receipt retention and production capacity. A successful local suite does not verify production TLS/ingress/storage IAM, Docker execution, remote CI, physical devices or independent penetration testing. No Batch 8 features are included.

Executed security evidence: same-tenant and cross-tenant linked-driver endpoint attacks; permission revalidation before receipt replay; direct PostgreSQL actor/tenant RLS SELECT and denied UPDATE; immutable-trigger rejection; payload/key tamper rejection; concurrent idempotent replay; audit-failure atomic rollback; process-restart replay; clock-skew flagging; browser quota failure and private-cache inspection; stale queue conflict; full local data clearing on logout. The browser lost-response test committed a command, dropped its response, retried the same UUID and observed exactly one milestone. Browser session revocation and same-account reauthentication were automated: pending work locks on rejection, survives login, and synchronizes exactly once.

Final browser recovery suite: 16/16; focused navigation/update suite: 2/2. These include explicit session rejection/relogin recovery, worker-update persistence and a deliberately stalled navigation. No security assertion was removed to obtain these results. Physical-device and production controls remain UNVERIFIED.

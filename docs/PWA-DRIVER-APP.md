# FleetPilot Driver PWA

The existing manifest now supplies the approved mint F/road artwork through an SVG viewport embedding the unchanged existing raster reference. No logo or original reference was regenerated or edited. Name FleetPilot Driver, standalone display, `/driver` start/scope, navy theme and cloud background remain consistent with the approved app.

`driver-worker.js` controls the driver scope. It never caches authenticated API responses, personalized Next.js HTML, cookies, evidence downloads or owner pages. It stores only `/driver-offline` (a public, non-personalized React boot document), public hashed Next static resources, Inter fonts, original brand reference and icon. Network-first driver document navigation falls back to that boot document on network failure or a 10-second navigation timeout. The boot document reads the controlled identity-scoped IndexedDB store and reuses DriverHomeContent, DriverTrips, TripDetail, DeliveryPanel and MobileBottomNav. Online protected routes retain their server identity guards.

`scripts/build-driver-worker.mjs` compiles the SAME TypeScript sync engine for the worker using the already installed TypeScript compiler. There is no added runtime dependency. The build fails if a runtime import is introduced into the dependency-free worker engine. Public `driver-sync.js` is generated; root build/dev commands regenerate it. Docker copies this build script. `worker-src 'self'` permits the worker without weakening the existing nonce-based page script CSP.

Updates do not use skipWaiting or delete IndexedDB. Existing open clients continue with their compatible worker; a replacement activates after old clients close. Public static build files are retained so a pending/offline boot is not invalidated by aggressive cache deletion. Cache/version pruning must preserve pending-client compatibility in a later release. Browser schema upgrades are additive, explicitly tested with pending Blob records.

Chrome installability is tested separately in a persistent profile because ordinary Playwright contexts are incognito and intentionally cannot install. Actual physical Android/iPhone installation, OS app-launch integration, Safari/iOS behavior and OS background execution are UNVERIFIED. Background Sync is opportunistic, never the sole recovery path. The driver must first visit and load the relevant trip online; uncached details cannot be fabricated offline.

New visual states are limited to compact connection/last-sync status, saved-work status, retry/review/discard actions, restored draft/evidence previews, and locked-cache recovery. Existing cards, alerts, buttons, hierarchy, Inter, navigation, colors and original assets remain the design authority. Owner screens remain server-confirmed and do not display device-only work.
